# 0007 — Each project is its own world

**Status:** accepted (2026-10-16, the owner: "o session mexe no repositório só do projeto que ele tá, tem que ser bem organizado"). **Where:** `server/foundation/care.mjs`, `server/sources/count.mjs`, `test/project-isolation.test.mjs`.

**Context.** session-map looks at many projects at once (here: session-map itself, cverino, surigo, dnd_mmorpg). Two things could go wrong between them: a write that lands in a project it was not asked about, and a rule written for one kind of project applied to another. The second one was real: the census called every folder named "vendor" a library, and in surigo the vendors' own app (459 files) lives there, so the program left a whole app out of what it knows.

**Decision.** (1) Everything the program keeps lives in its own folder under the project's id; a round for one project writes nothing in any repository. (2) The only door into a repository is `applyOp`, which refuses a path outside the project's folder, inside `.git` or in a secret file, and obeys that project's care mode; the few other writes (the map clerk for the chat of that project, a safety ref and a worktree for another AI's run, a new project's folder) are named in `docs/architecture/server.md` item `sv26`. (3) A rule that depends on how a project is organized reads the project's own files, not a name: a vendor folder is a library only where Composer's or Go's marks are among the project's files, and only test and fixture folders are samples. What a project wants differently it says in its own config (`vendored`), kept in the project or in session-map's folder, never guessed.

(4) "Tudo em dia?" and every other look are made one project at a time, each in its own try: what is wrong in one never stops the reading of another, and what is said about a project does not depend on the others.

**Consequences.** One project's numbers cannot be moved by another's. A project that commits third-party code under a plain name must list it in `vendored`, or the Foundation reads it as the project's own: visible noise instead of a silent omission. `test/project-isolation.test.mjs` proves the separation; any new write path must go through the door or be named and tested.
