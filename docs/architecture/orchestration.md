# Orchestration

A senior conductor chat per project that sees the whole map, hands focused work to activity chats, hears back from each one and weighs every proposal like a board would. It is the owner's single place to say what they want; the activity chats do the work.

## How it works

Each project gets one orchestration chat, pinned on top of the conversation list and on the root of the map. It starts from a compact summary of the project (architecture, open items per part, what waits for the owner, what is running, the latest decisions) instead of the whole history. When it starts a piece of work it opens an activity chat on the right item, with the model it picked, always after a confirmation. The activity ticks its item when done and reports back; when the orchestration grows long it summarizes and continues.

## Where in the code

- `server/chat/`
- `server/brain/`
- `server/ai/` — the arsenal and the engine: `providers.mjs` (the four engines' APIs), `router.mjs` (who takes which kind), `policy.json` + `policy.mjs` (the one model table), `brain.mjs` (the entry weighing), `quota.mjs` + `engine.mjs` + `groups.mjs` + `contract.mjs` + `efforts.mjs` (failover, engine choice, exit contract, per-engine levels), `brainpanel.mjs` + `brainroute.mjs` + `functions.json` (the Cérebro tab), `ask.mjs` and `runner.mjs` (the dispatch), `prices-watch.mjs` (the price pages watch, `or51`)
- `server/background.mjs`

## Rules that must not break

- Quality is rule number one; saving money is a consequence of choosing well, never the goal.
- An activity chat is started by the orchestration on its own, in the Autonomous way, tied to an item code; the owner sees it in the list and can stop it (the owner's choice on 2026-10-10, `id90`; before, it waited for a confirmation).
- Money, accounts, contracts and business priority belong to the owner: a recommendation plus a one-click confirmation.
- The mode `bypassPermissions` is never used.
